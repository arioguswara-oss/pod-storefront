POD Simple Checkout 1.2.1 — installation, acceptance and rollback

BEFORE LIVE ACTIVATION

The owner must explicitly approve live upload/activation. This development task
does not grant that approval. GraphicTeeStore.com remains the real-world testing
website; do not create or require an extra hosted staging site.

1. Obtain a complete database backup including WooCommerce/HPOS order tables,
   and file backups of plugins, theme, uploads and configuration. Store securely
   outside the repository/webroot. Verify archive readability and restore access.
2. Record WordPress/PHP/WooCommerce versions, the current active plugin version,
   checkout page ID/type, guest checkout rules, required fields/extensions,
   shipping methods/taxes/coupons, current gateways and cache exclusions.
3. Verify the ZIP's SHA-256 against the accompanying SHA256SUMS. The root folder
   must be pod-simple-checkout/. There are no development dependencies inside.
4. Confirm the mode displayed under WooCommerce > POD Simple Checkout. The owner reports Classic Checkout on the live website. Confirm the current
   page/type before activation; this release does not change checkout pages.

INSTALL AND CONFIGURE (AFTER APPROVAL)

Upload pod-simple-checkout-v1.2.1.zip in WordPress Admin > Plugins > Add New >
Upload Plugin. If upgrading the prior plugin, use WordPress's normal replacement
confirmation after backup. Activate the plugin. No CLI, npm or Composer is needed.

Open WooCommerce > POD Simple Checkout. Keep cart replacement OFF initially.
Buy Now, AJAX, direct checkout and checkout UI default to ON. No store options
are changed on activation; these are plugin defaults. Saving the settings writes
only pod_sc_settings via the WordPress Settings API and a manage_woocommerce
capability check. Gateways and cache plugins are not reconfigured.

OWNER-APPROVED ACCEPTANCE CHECKS

Start with read-only browsing at 320/390/768/1440px: layout, variation options,
price display, stock and native field labels. Compare before/after public URLs.

Cart operations write a visitor session and can fire tracking/extension hooks;
obtain explicit authorization before any live cart smoke test. In a clean guest
session check Add to Cart, counts, variable selection, Buy Now, preserved bag,
shipping/address changes, coupon validation, privacy/terms and visible errors.
Keep native cart accessible. Remove agreed test items afterward.

Do not submit real orders or test real payments under this development scope.
Live paid-order/gateway verification belongs to a separately authorized process.
Zero-value orders in the automated suite are synthetic and local only.

LiteSpeed configuration stays untouched. Review existing cache exclusions;
verify dynamic responses are not cached after the owner authorizes installation.
Redis is not enabled. CDN/edge/third-party cache behavior remains an operator
check; per-response headers cannot repair a separately misconfigured upstream.

ROLLBACK

Deactivate only POD Simple Checkout via WordPress Admin. Native WooCommerce
product forms, cart and checkout continue, using the same products/URLs/orders.
If wp-admin is unavailable, use authorized hosting file-manager access to rename
this plugin folder, or existing WP-CLI access: wp plugin deactivate pod-simple-checkout

Retain the ZIP and prior plugin package. Reinstall the previous version only if
needed. No theme switch or gateway configuration change is part of rollback.
Do not restore the database as the first step: doing so can erase newer orders.
Plugin settings are retained; short-lived request records expire normally.

SHOPPING SHEETS CHECKPOINT

Enabled with the existing AJAX setting; no new options or automatic migration.
Catalog Choose Options has a canonical product URL. Header bag has the native
cart URL. Native dialog/fetch unavailable or AJAX off: use those URLs instead.
The sheet Buy Now always keeps existing buyer items, including when the older
optional replacement setting is on. Keep that legacy option OFF; it still
applies to standard product-page forms outside the sheet.

Before owner-approved installation retain pod-simple-checkout-v1.1.0.zip. For
a UX rollback, disable AJAX to restore canonical product/cart navigation, or
deactivate this plugin and reinstall the prior reviewed version. Do not restore
an old database over new orders. Existing theme files remain unchanged.

After approval test catalog and bag overlays at 320x740, 390x844, 768x1024 and
1440x900, keyboard focus/close, unavailable options, cart count/quantity/remove,
refresh/back, shipping/tax/coupon totals and the canonical cart. Test actual
extensions/cache/browser stack before widening buyer testing. No orders or
gateway changes are authorized by these instructions.

PHASE 3 UPGRADE FROM 1.1.0

Retain pod-simple-checkout-v1.1.0.zip and a verified complete files/database
backup before a separately approved upgrade. Replace the plugin through the
WordPress dashboard. No page conversion, field deletion, order migration or
store setting write occurs on activation; existing plugin settings are kept.

Checkout UI ON enhances compatible native Classic templates. Blocks, unsupported
builders/address fields and billing-only shipping rules keep native compatibility
presentation. Same-address is default only for matching/blank native addresses;
saved differing addresses remain separately editable. Billing/shipping phone and
all required fields remain. Unknown addon fields trigger native layout.

Verify actual addon/gateway DOM, country rules, address autocomplete, taxes and
shipping in a separately authorized acceptance test. No paid transaction is
authorized. A sticky button is not forced over fields, errors, consent or the
keyboard; normal native placement is the safe fallback.

Rollback the checkout presentation with Checkout UI OFF (product/cart sheets
remain available), or replace only this plugin with retained v1.1.0. Do not
restore an old DB over new orders or switch the reviewed theme/gateways.

PATCH UPGRADE FROM 1.2.0
Retain v1.2.0 ZIP and verified backup before owner-approved replacement. This
patch only enhances visible submit copy for eligible generic native labels.
No settings or schema migration. Roll back by reinstalling v1.2.0; do not
restore an old DB over new orders. Gateway-specific and SDK labels remain native.
